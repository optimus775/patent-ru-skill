# Российская патентная заявка

Этот skill ведет агента от анализа проектных материалов к комплекту черновых документов российской заявки на изобретение: **описание изобретения**, **формула изобретения**, **реферат**, **фигуры/чертежи** и внутренние заметки по уровню техники. Подробные инструкции разделены по файлам в `prompts/`; перед каждым этапом агент должен прочитать соответствующий prompt.

## Нормативная рамка

- Базовая структура описания ориентирована на действующие требования Роспатента к заявке на изобретение: название, область техники, уровень техники, раскрытие сущности, краткое описание чертежей, осуществление изобретения.
- Основной режим по умолчанию: **заявка на изобретение**. Полезная модель допускается как вариант на этапе intake; промышленный образец не входит в текущий scope.
- Агент готовит технический черновик для дальнейшей работы патентного специалиста; он не должен выдавать юридические гарантии патентоспособности.

## Триггеры

Включай skill, когда пользователь просит:

- найти патентоспособные технические решения, патентные признаки, формулу, реферат, описание изобретения;
- подготовить российскую патентную заявку, материалы для Роспатента, чертежи/фигуры, уровень техники, раскрытие сущности;
- сравнить решение с уровнем техники или провести первичную проверку новизны;
- доработать уже созданное описание, формулу, реферат или фигуры.

Поддерживаемые короткие вызовы: `/patent-ru-skill`, `/patent-ru`, `/патент`, `/заявка`.

## Инструменты и источники

| Задача | Рекомендуемый способ |
|---|---|
| Загрузка инструкций | `Read` соответствующего файла из `prompts/` |
| Сканирование проекта | Поиск и чтение документации, кода, схем; большие репозитории сначала сужать через `Grep`/`Glob` |
| Word/PPT как исходные материалы | Сначала конвертировать `.docx`/`.pptx` в Markdown через `tools/docx_to_md.py` и `tools/pptx_to_md.py`, затем читать полученный `.md` |
| Поиск уровня техники | Перед выполнением читать `prompts/prior_art_search.md`; использовать Google Patents через `WebSearch` и официальный поиск ФИПС через `tools/fips_search.py` + Browserless |
| Фигуры и схемы | В черновике использовать fenced `mermaid`; перед выдачей прогонять `tools/mermaid_render.py`, который заменяет схемы на PNG и по умолчанию создает `.docx` |
| Экспорт в Word | `tools/md_to_docx.py` или автоматический вызов из `tools/mermaid_render.py` |
| Итерации | Для нового материала читать `iteration_context.md` + `merger.md`; для исправлений читать `iteration_context.md` + `correction_handler.md` |

## Prompt Файлы

| Этап | Файл | Назначение |
|---|---|---|
| Step 1 | `prompts/intake.md` | Границы заявки, тип объекта, контактные поля, исходные материалы |
| Step 2 | `prompts/project_scan.md` | Сканирование материалов, включая обязательную конвертацию Office-файлов |
| Step 3-4 | `prompts/patent_points_analyzer.md` | Кандидатные решения, единый изобретательский замысел, выбор объекта заявки |
| Step 5 | `prompts/prior_art_search.md` | Поиск уровня техники и фиксация отличительных признаков |
| Step 5.5 | `prompts/patentability_overlap_assessment.md` | Предварительная техническая оценка полного или частичного перекрытия найденными источниками |
| Step 6 | `prompts/disclosure_preview.md` | Краткое согласование направления перед полной сборкой документов |
| Step 7 | `prompts/disclosure_builder.md` + `prompts/template_reference.md` | Структура российского комплекта: описание, формула, реферат, фигуры |
| Step 8 | `prompts/disclosure_self_check.md` | Внутренняя проверка достаточности раскрытия, формулы, терминологии и фигур |
| Итерация | `prompts/iteration_context.md` | Общие правила доработки уже созданного комплекта |
| Итерация | `prompts/merger.md` | Включение новых материалов в существующий комплект |
| Итерация | `prompts/correction_handler.md` | Исправление ошибок, формулы, терминов, фигур или структуры |

## Основной Процесс

1. Прочитать `intake.md` и собрать минимальные границы заявки.
2. Прочитать `project_scan.md` и просканировать материалы; `.docx`/`.pptx` обязательно конвертировать перед чтением.
3. Прочитать `patent_points_analyzer.md`, выделить 3-5 кандидатных решений и выбрать основное решение или группу решений.
4. Прочитать `prior_art_search.md`, выполнить поиск уровня техники и сформировать таблицу ближайших источников.
5. Прочитать `patentability_overlap_assessment.md` и сохранить отдельный отчет о перекрытии уровнем техники.
6. Если отчет выявил `полное перекрытие`, остановить сборку заявки и выдать отчет; иначе прочитать `disclosure_preview.md` и показать направление, если пользователь не просил пропустить preview.
7. Прочитать `disclosure_builder.md` и `template_reference.md`, затем собрать комплект документов заявки.
8. Прочитать `disclosure_self_check.md`, выполнить внутреннюю проверку и исправить документ до выдачи.

## Итерационный Режим

Если пользователь работает с уже созданным комплектом, не запускай полный анализ заново без явной просьбы. Определи тип задачи:

- **Новые материалы / расширение**: читать `iteration_context.md`, затем `merger.md`.
- **Ошибка / противоречие / правка формулы или терминов**: читать `iteration_context.md`, затем `correction_handler.md`.

Итог каждой итерации сохраняется новым файлом `{название_изобретения}_{YYYYMMDDHHmmss}.md` и одноименным `.docx`, если пользователь не попросил иной путь или перезапись. В каталоге дела ведется `revision_dialog_log.md`.
