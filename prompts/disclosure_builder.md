# Сборка документов российской заявки (Step 7)

Подробные шаблоны и примеры формулировок см. в `template_reference.md`.

## 7.1 Выходной комплект

Итоговый Markdown должен содержать четыре основных документа:

1. `Описание изобретения`
2. `Формула изобретения`
3. `Реферат`
4. `Фигуры` или перечень фигур с ссылками на изображения

Если пользователь просит только часть комплекта, готовь только указанную часть, но не нарушай связь: формула должна быть основана на описании, а реферат не должен вводить новые признаки.

## 7.2 Структура описания

Используй российскую структуру:

```markdown
# Материалы заявки на изобретение

## Заявочные сведения

## Описание изобретения

### Название изобретения

### Область техники, к которой относится изобретение

### Уровень техники

### Раскрытие сущности изобретения

### Краткое описание чертежей

### Осуществление изобретения

## Формула изобретения

## Реферат

## Фигуры
```

### Уровень техники

- Приводи ближайшие аналоги и источники с проверяемыми ссылками.
- Указывай недостатки уровня техники, которые относятся к технической проблеме.
- Не перегружай раздел полным журналом поиска; подробности можно оставить в рабочих заметках.

### Раскрытие сущности

Раздел должен раскрывать:

- техническую проблему;
- технический результат;
- совокупность существенных признаков;
- причинно-следственную связь признаков с результатом;
- варианты реализации и зависимые признаки;
- для группы решений: связь единым изобретательским замыслом.

### Осуществление изобретения

Пиши так, чтобы специалист мог реализовать решение:

- состав и взаимодействие компонентов;
- порядок операций;
- условия выполнения;
- параметры, диапазоны, формулы и их смысл;
- примеры реализации;
- ссылки на фигуры и позиции.

## 7.3 Формула изобретения

Формула должна ясно выражать сущность и быть полностью основана на описании.

- Независимый пункт содержит родовое понятие, назначение и существенные признаки.
- Зависимые пункты раскрывают частные признаки, варианты, параметры, условия и предпочтительные реализации.
- Для способа используй глаголы в третьем лице множественного числа: `получают`, `определяют`, `формируют`, `передают`.
- Для устройства/системы раскрывай компоненты и связи между ними.
- Для машиночитаемого носителя указывай, что программа обеспечивает выполнение операций способа на программируемом средстве.
- Не добавляй в формулу признак, которого нет в описании.

## 7.4 Реферат

Реферат служит для информирования и не определяет объем охраны. Он должен кратко включать:

- название или объект изобретения;
- область техники или применения, если это не ясно из названия;
- сущность с существенными признаками независимого пункта;
- решаемую техническую проблему;
- технический результат;
- при необходимости ссылку на выбранную фигуру.

Рекомендуемый объем: до 1000 печатных знаков. Не вводи в реферат признаки, которых нет в описании и формуле.

## 7.5 Фигуры

- В черновике допускаются fenced `mermaid` схемы: структурная схема, блок-схема способа, последовательность операций, пример структуры данных.
- В разделе `Краткое описание чертежей` перечисляй `Фиг. 1`, `Фиг. 2` и кратко поясняй, что изображено.
- В тексте `Осуществление изобретения` ссылайся на фигуры и позиции согласованно.
- Перед выдачей итогового файла запусти `tools/mermaid_render.py`, чтобы заменить mermaid на PNG и сформировать `.docx`.

## 7.6 Имена файлов

Если пользователь не указал путь, сохраняй итоговый комплект в `outputs/{case_slug}/`.

Итоговые файлы:

```text
{нормализованное_название_изобретения}_{YYYYMMDDHHmmss}.md
{нормализованное_название_изобретения}_{YYYYMMDDHHmmss}.docx
```

Правила:

- название брать из раздела `Название изобретения`;
- удалить символы, недопустимые в Windows-пути: `\ / : * ? " < > |`;
- ограничить основу имени примерно 80 символами;
- не перезаписывать старые версии без прямой просьбы пользователя;
- для итераций использовать те же правила.

## 7.7 Финальная команда

Для черновика с mermaid:

```bash
python3 tools/mermaid_render.py -i "<draft>.md" -o "<название_изобретения_YYYYMMDDHHmmss>.md"
```

Скрипт по умолчанию создаст одноименный `.docx`. Если Word не создан, выполни подсказанную команду `md_to_docx.py`.

## Запреты

- Не включай в итоговый документ self-check, историю работы агента, ссылки на skill или учебные примеры.
- Не оставляй посторонние заголовки исходных шаблонов.
- Не обещай выдачу патента или окончательную патентоспособность.
