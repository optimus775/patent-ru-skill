# Внутренняя проверка комплекта (Step 8)

Self-check выполняется агентом перед выдачей и не включается как раздел в итоговый документ, если пользователь прямо не попросил отчет.

## Достаточность раскрытия

- [ ] Описание позволяет специалисту осуществить изобретение без изобретательских догадок.
- [ ] Раскрыты все существенные признаки независимых пунктов.
- [ ] Для каждого технического результата указана причинная связь с признаками.
- [ ] Варианты реализации не противоречат независимому пункту.
- [ ] Для IT-решений раскрыты программируемые средства, данные, операции и технический контекст.

## Формула

- [ ] Независимые пункты основаны на описании и не содержат новых нераскрытых признаков.
- [ ] Родовое понятие отражает назначение объекта.
- [ ] Зависимые пункты действительно уточняют независимые.
- [ ] Для группы решений есть единый изобретательский замысел.
- [ ] Термины формулы используются единообразно в описании.

## Уровень техники

- [ ] Для релевантных источников есть проверяемые ссылки.
- [ ] Недостатки уровня техники связаны с заявленной технической проблемой.
- [ ] Отличительные признаки не противоречат найденным источникам.
- [ ] Если использован CNIPA `abstract`, пересказ источника соответствует его содержанию.

## Реферат и фигуры

- [ ] Реферат не превышает разумный объем и не вводит новые признаки.
- [ ] Все фигуры перечислены в `Кратком описании чертежей`.
- [ ] Все ссылки на фигуры и позиции согласованы.
- [ ] Mermaid-схемы преобразованы в PNG для итогового файла, если комплект выдается как `.md` + `.docx`.

## Файлы и чистота документа

- [ ] Итоговые файлы названы `{название_изобретения}_{YYYYMMDDHHmmss}.md` и `.docx`, если пользователь не задал другое.
- [ ] Старые версии не перезаписаны без явной просьбы.
- [ ] В документе нет self-check, служебных рассуждений агента, ссылок на skill, учебный репозиторий или китайские заголовки исходного шаблона.
- [ ] При итерации обновлен `revision_dialog_log.md`.

## Действие при проблемах

Если найдено нарушение, исправь итоговый документ перед выдачей. Если исправить невозможно из-за нехватки данных, явно отметь недостающий факт в ответе пользователю и не маскируй пробел выдуманным раскрытием.
