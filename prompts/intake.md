# Intake: границы заявки (Step 1)

## Назначение

Перед анализом материалов быстро зафиксируй рамки будущей российской заявки. Если пользователь хочет сразу работать с уже имеющимися файлами, не задерживай процесс: недостающие поля можно оставить как предположения и явно отметить их в preview.

## Минимальные вопросы

Задавай только те вопросы, ответы на которые нельзя вывести из материалов.

### Q1: тема и объект

```
Опишите техническую тему одной фразой и укажите, что предполагается защищать: способ, устройство/система, машиночитаемый носитель, применение, группа решений или пока не определено.
```

### Q2: тип заявки

```
Работаем как с заявкой на изобретение по умолчанию? Если нужен вариант полезной модели, укажите это явно.
```

### Q3: контактные и заявочные поля

```
Нужно ли заполнить поля заявителя, автора, технического контакта и предполагаемого названия? Если данных нет, оставлю "подлежит уточнению".
```

## Что зафиксировать

- техническая область и назначение решения;
- предполагаемый объект охраны;
- исходные материалы и каталог сканирования;
- ограничения по раскрытию: что можно включать, что нужно обезличить;
- желаемый выход: полный комплект `.md`/`.docx`, только формула, только описание, доработка старого файла.

Суммируй подтвержденное в 3-6 коротких пунктах и переходи к `project_scan.md`.
