# Контекст итераций

## Когда читать

Читай этот файл, если пользователь дорабатывает уже созданный комплект заявки: добавляет материал, исправляет ошибки, меняет формулу, реферат, фигуры, терминологию или разделы описания.

Не запускай полный цикл поиска решений заново, если пользователь явно работает с существующим файлом. Исключение: он прямо просит заново выделить патентные решения или провести новый поиск уровня техники.

## Выбор сценария

| Намерение пользователя | Следующий prompt |
|---|---|
| Добавить документы, код, примеры, варианты реализации | `merger.md` |
| Исправить факты, противоречия, формулу, стиль, термины, фигуры | `correction_handler.md` |

## Входные данные

- текущий базовый `.md` комплект;
- новые материалы или указания пользователя;
- существующие фигуры, PNG и `.docx`, если они есть;
- журнал `revision_dialog_log.md`, если он уже создан.

## Выход

Создай новый итоговый файл, не перезаписывая старый:

```text
{нормализованное_название_изобретения}_{YYYYMMDDHHmmss}.md
{нормализованное_название_изобретения}_{YYYYMMDDHHmmss}.docx
```

Если пользователь явно требует перезапись конкретного файла, следуй его указанию, но все равно сообщи о риске потери версии.

## Журнал правок

После успешной итерации обнови файл `revision_dialog_log.md` в каталоге дела. Используй `tools/iteration_dialog_log.py`:

```bash
python3 ${CLAUDE_SKILL_DIR}/tools/iteration_dialog_log.py \
  --case-dir "<каталог дела>" \
  --kind merge \
  --user "<краткое содержание запроса пользователя>" \
  --summary "<краткий итог правки>" \
  --artifacts "<file.md>,<file.docx>"
```

Для исправлений используй `--kind correct`.

Если скрипт недоступен, создай или дополни `revision_dialog_log.md` вручную с теми же полями: локальное время, UTC, тип, краткое содержание запроса, файлы результата, краткий итог.

## Рекомендуемый порядок

1. Прочитать базовый `.md`.
2. Прочитать новые материалы или указания.
3. Выбрать `merger.md` или `correction_handler.md`.
4. Внести изменения в полный текст комплекта.
5. Выполнить проверки из `disclosure_self_check.md`.
6. Сохранить новый `.md`, прогнать `mermaid_render.py` и получить `.docx`.
7. Обновить `revision_dialog_log.md`.
8. В ответе указать пути и дать краткий итог.
