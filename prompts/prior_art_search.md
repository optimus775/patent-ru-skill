# Поиск уровня техники (Step 5)

## Когда выполнять

До сборки полного комплекта документов или во время нее обязательно собрать первичный уровень техники. Выводы используются в разделах `Уровень техники`, `Раскрытие сущности изобретения`, формуле и отличительных признаках.

## Временный канал поиска

Поиск по ФИПС будет отдельной задачей. До его добавления сохраняется текущий CNIPA-first workflow из исходного skill:

1. Сначала использовать `tools/cnipa_epub_search.py` для поиска в китайской базе публикаций CNIPA.
2. Если CNIPA недоступен, не дает релевантных результатов или тема явно требует иных источников, дополнять WebSearch, Google Patents, Espacenet, научные публикации и другие проверяемые источники.
3. Не менять CNIPA-скрипты и их поведение в рамках российской адаптации.

## CNIPA: правила вызова

Перед запуском сформируй 2-8 поисковых единиц из темы и существенных признаков. Каждая единица должна быть осмысленным термином или словосочетанием, а не длинной фразой целиком и не слишком общим словом.

Агент выполняет отдельный вызов на каждую поисковую единицу:

```bash
python3 ${CLAUDE_SKILL_DIR}/tools/cnipa_epub_search.py "<поисковая единица>"
```

Разбирай строку `EPUB_HITS_JSON:` из stdout и объединяй результаты по `pub_number`, при его отсутствии по `link`, затем по нормализованному названию. Stderr с `EPUB_NOTE:` или `EPUB_MERGE:` не считать ошибкой сам по себе.

## Использование abstract

Если результат CNIPA содержит непустой `abstract`, описание источника в рабочих заметках и в разделе `Уровень техники` должно опираться на понимание этого abstract:

- область применения;
- какую проблему решает источник;
- какие средства или операции использует;
- какой эффект заявлен;
- чем источник ограничен относительно текущего решения.

Не копируй abstract длинными фрагментами в итоговый документ; пересказывай своими словами. Если abstract отсутствует, найди дополнительный проверяемый источник или отметь, что источник нельзя использовать для содержательного сравнения без дополнительной проверки.

## Дополнительные источники

Используй, когда CNIPA недостаточен:

- Google Patents для стабильных страниц патентов и семейств;
- Espacenet, WIPO Patentscope, USPTO, EAPO, если релевантно;
- научные публикации через DOI, издателя, arXiv или другую устойчивую страницу;
- сайты производителей и документацию только как непатентный уровень техники, если дата публикации проверяема.

## Что фиксировать

Для каждого релевантного источника:

| Поле | Требование |
|---|---|
| Идентификатор | номер публикации, патента, DOI или иной стабильный идентификатор |
| Название | как в источнике |
| Ссылка | проверяемый URL; не придумывать ссылки |
| Дата | дата публикации/приоритета, если доступна |
| Суть | краткое содержание технического решения |
| Общие признаки | что совпадает с текущим решением |
| Ограничения | почему источник не решает текущую техническую проблему полностью |
| Отличительные признаки | что должно перейти в раскрытие сущности и формулу |

## Формулирование для заявки

В разделе `Уровень техники` не нужно включать весь журнал поиска. Дай сжатый обзор ближайших источников и их недостатков. Заверши выводом, какие признаки отличают заявляемое решение и почему они связаны с техническим результатом.

## Запреты

- Не утверждать патентоспособность как установленный факт.
- Не писать в российский комплект фиктивные ссылки, даты или номера.
- Не смешивать китайскую терминологию исходного skill с русской структурой заявки.
