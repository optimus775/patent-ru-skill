# Сканирование проектных материалов (Step 2)

## Цель

Извлечь из исходников и документов сведения, которые нужны для российской заявки: техническая проблема, ближайшие аналоги, существенные признаки, причинно-следственная связь с техническим результатом, варианты осуществления и материал для фигур.

## Приоритеты

| Приоритет | Материалы | Что искать |
|---|---|---|
| 1 | Патентные или заявочные материалы | старые описания, формулы, заявки, патентные заметки, prior art, списки отличий |
| 2 | Архитектурные и проектные документы | назначение системы, блоки, алгоритмы, процессы, ограничения, технический эффект |
| 3 | Код и конфигурация | реализованные признаки, порядок операций, условия, параметры, обработка ошибок, интеграции |
| 4 | Эксперименты и результаты | измеримые эффекты, сравнения, примеры, тестовые сценарии, метрики |
| 5 | Сопроводительные материалы | презентации, письма, meeting notes, схемы, таблицы терминов |

## Обязательная конвертация Office

Если в зоне сканирования есть `.docx`, `.pptx` или `.ppsx`, сначала конвертируй их в Markdown и только потом анализируй:

```bash
python3 ${CLAUDE_SKILL_DIR}/tools/docx_to_md.py -i "<path>/<file>.docx" -o "<path>/<file>.md"
python3 ${CLAUDE_SKILL_DIR}/tools/pptx_to_md.py -i "<path>/<file>.pptx" -o "<path>/<file>.md"
```

Старые `.doc` и `.ppt` не поддерживаются скриптами; попроси пользователя сохранить их как OOXML или предоставь анализ на основе доступных файлов. Полученный `_media/` каталог сам по себе не является обязательным для распознавания, если картинки уже представлены ссылками в Markdown.

## Как читать материалы

- Большой репозиторий сначала сузь через имена файлов, README, docs, архитектурные папки и поисковые запросы по ключевым терминам.
- Для каждого важного факта сохраняй путь к источнику, чтобы затем проверить, что формула основана на описании и материалах.
- Не включай коммерческие имена, внутренние коды, клиентов и точные конфиденциальные числа без необходимости; такие данные замени обобщением.

## Что извлечь

Собери рабочую таблицу:

| Поле | Содержание |
|---|---|
| Назначение | что делает решение и для какого технического контекста |
| Техническая проблема | какой недостаток прототипа или уровня техники устраняется |
| Существенные признаки | признаки, без которых технический результат не достигается |
| Технический результат | проверяемый эффект, желательно измеримый или объективно наблюдаемый |
| Варианты | альтернативные реализации, параметры, условия, зависимые признаки |
| Фигуры | какие схемы нужны: система, последовательность операций, структура данных, пример |
| Доказательная база | ссылки на файлы, фрагменты кода, документы, таблицы, эксперименты |

## Ограничения

- Не превращай бизнес-эффект в технический результат без технической причинности.
- Не добавляй в будущую формулу признаки, которые не раскрыты в материалах и не могут быть технически обоснованы.
- Если данных недостаточно для осуществления изобретения специалистом, отметь пробелы до этапа сборки документов.
